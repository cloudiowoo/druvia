# Druvia 商业化战略文档

## 概述

基于项目现状和市场分析，确定 Druvia 的商业化方向和差异化定位。

**创建日期**: 2026-03-10
**状态**: 已批准

---

## 一、核心定位

> **国内开发者的自托管 BaaS，开箱即用的中国区集成**

### 与 Supabase 的差异化

| 维度 | Druvia | Supabase |
|------|--------|----------|
| 主要模式 | 自托管优先 | 云托管优先 |
| 数据隔离 | Schema-per-Tenant（强隔离） | RLS（行级） |
| 界面语言 | 中文原生 | 英文 |
| 国内 SSO | 微信/钉钉/飞书开箱即用 | 无 |
| 国内 AI | 通义/文心/GLM 集成 | 无 |
| 自托管成本 | 低（架构简洁） | 高（组件多） |

### 核心价值主张

```
Supabase 卖的是：「我帮你运维」
Druvia 卖的是：「帮你自己运维得更轻松 + 中国区开箱即用」
```

## 二、目标市场

### 用户画像

```
┌─────────────────────────────────────────────────────────────┐
│ 第一梯队（核心用户）                                          │
│ • 独立开发者 / 小型创业团队                                   │
│ • 需要快速搭建后端，不想管理基础设施                           │
│ • 预算有限，倾向自托管降低成本                                │
│ • 需要微信/钉钉等国内登录集成                                 │
├─────────────────────────────────────────────────────────────┤
│ 第二梯队（增长用户）                                          │
│ • 中小企业技术团队                                            │
│ • 需要多项目管理、团队协作                                    │
│ • 有数据合规要求（金融、医疗、政务）                          │
├─────────────────────────────────────────────────────────────┤
│ 第三梯队（企业用户）                                          │
│ • 大型企业内部平台                                            │
│ • 多租户 SaaS 产品开发商                                      │
│ • 需要私有化部署 + 商业支持                                   │
└─────────────────────────────────────────────────────────────┘
```

### 典型场景

- 微信小程序后端
- 企业内部工具（钉钉/飞书集成）
- AI 应用后端（需要国内 AI 服务）
- 从 Supabase/Firebase 迁移的项目

**集成方案**：

```
方案 A：Edge Functions 内置 AI SDK（推荐）
├── 在 Deno Worker 中预装 AI 客户端
├── 用户代码直接调用
└── 示例：const ai = Druvia.ai('qwen'); await ai.chat(...)

方案 B：AI Gateway 代理
├── API 层统一代理各 AI 服务
├── 统一鉴权、限流、日志
└── 用户通过 Druvia API 调用 AI
```

| Edge Functions | ⭐⭐⭐ 中 | Deno 代码可能兼容 |

## 六、竞争策略

### 市场切入点

1. **垂直场景**：微信小程序后端、企业内部工具
2. **迁移用户**：Supabase 国内用户（网络慢、无国内集成）
3. **成本敏感**：自托管降低云服务费用

### 营销策略

- 技术博客：「从 Supabase 迁移到 Druvia」系列
- 视频教程：「5 分钟搭建微信小程序后端」
- 开源社区：GitHub、掘金、V2EX
- 开发者活动：技术 Meetup、黑客松赞助

## 七、风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| 大厂入局 | 高 | 聚焦自托管 + 国内集成细分市场 |
| 开源维护成本 | 中 | 建立贡献者激励机制 |
| 商业化转化低 | 中 | 先建社区口碑，再推商业服务 |
| AI 时代功能易复制 | 中 | 卖服务和时间，不卖功能 |
